## 1. PRIMARY-SOURCE READINGS

### IRCA (Wang, Zhou, Wu, Deng, Wu, Lee, Wang; NDSS 2025; full PDF read) [PRIMARY]
- Domain: multi-sensor-fusion (MSF) perception in ADS (Autoware, cross-check on Apollo). Modules form a DAG (Fig. 1).
- Failure and fault are DEFINED against GROUND TRUTH: fault modes MO/GO/MC/PE are "inconsistency of the object O with the ground truth G_t" (Sec. II-B, eq. 1-5). Per-module fault-mode vectors are computed by runtime monitoring against G_t.
- Input: an already identified failure scenario (replayable), per-module outputs, the module DAG (built from expert knowledge of the MSF configuration), and an "intervention oracle".
- Intervention oracle = "the expected output of each module ... contains the actual object information such as position and classification. In simulations, provided by the simulators, while in physical implementations, we utilize recorded event logs" (Sec. IV-B). I.e. it needs ground-truth object data.
- RE-EXECUTES: Algorithm 1 replaces a suspect module's output with the oracle output and "triggers a re-execution of the MSF"; branch pruning + node pruning choose intervention targets; synchronous mode so failure is reproducible. Efficiency is reported as number of interventions / minutes.
- No learned classifier, no labelled-fault training set. The causal structure is the hand-built DAG (plus constraints); causal test is by intervention, not by consistency checks.
- Output: causal PATH of modules (ordered subset) plus the fault modes (MO/GO/MC/PE) inside each causal module. Assumes OR-relationship (any fault on the path is sufficient); AND-type collaborative faults explicitly left open.
- Evaluation: real Autoware GitHub issues (Dataset 1) + synthetic faults injected at module OUTPUTS (Dataset 2), single and multiple; baselines DVCA, AID, RCD. F1 95.39 % real, ~89.8 % recall synthetic. Fault injection is at object-level message outputs, NOT sensor-level and NOT configuration-level.
- It cites Antonante et al. (probabilistic diagnostic graph) and CaRE in related work and dismisses CaRE as "not suitable ... developed for multi-dimensional system metrics".

### Han, Taheri, Chung, Hadaegh 2025 (arXiv 2509.18460; full PDF read) [PRIMARY]
- Framework for fault detection and isolation (FDI) in robot perception via counterfactual reasoning with an SCM and do-operator; passive (belief update / likelihood-ratio test) and active (MCTS+UCB chooses control input maximizing "Effective Information").
- Inputs: reliability tests d(.) on intermediate module outputs (e.g. number of detected features, image sharpness, optical flow, inter-frame transformation); a state estimator for the belief; control authority for the active variant.
- Requires per-hypothesis fault models: p(r | state, fault mode psi_i) "can be obtained from the experiment in controlled environments where the fault scenario has been set up"; in the experiment: "we sample 30 fault scenarios for each hypothesis ... as if obtained from offline experiments", plus a fault-free baseline distribution (effect distribution ED under H0). So: it NEEDS labelled fault experiments and a fault-free reference distribution.
- "Counterfactual" = prediction of test outcomes under a hypothesized fault via the learned distributions, not re-running modules on replaced inputs.
- Assumption 1: exactly ONE fault at a time. Fault hypotheses are sensor/environment scenarios (dynamic scene, sensor damage, visually deprived); output = posterior over {healthy, H1, H2, H3}. It does NOT localize to a layer/module of a pipeline.
- Evaluation: simulation only (asteroid proximity-navigation; image formation / front-end / PnP+EKF back-end); baselines threshold-based passive FDI and random control input.

### CaRE (Hossen, Kharade, Schmerl, Camara, O'Kane, Czaplinski, Dzurilla, Garlan, Jamshidi; RA-L 2023; arXiv 2301.07690; full PDF read) [PRIMARY]
- Input: OBSERVATIONAL data = performance metrics/objectives measured by running the mission 400 times under different configuration settings (Reval tool, Gazebo and physical Husky/Turtlebot3). So it needs MANY RUNS of the system; not a single finished run.
- "Faulty" = performance objective worse than the 99th percentile of the collected runs (needs a reference distribution of non-faulty runs). Ground truth for evaluation: 20 functional faults with 2-4 root causes each.
- Learns causal structure with FCI under structural constraints (3-layer SCM: configuration options -> intermediate performance metrics -> objectives), then extracts causal paths and ranks them by average causal effect (do-operator estimate). Baseline: CBI (statistical debugging).
- Output: ranked CONFIGURATION OPTIONS (software+hardware) as root causes. Does not localize to a pipeline module/layer of the output structure; not code-level.
- Limitations stated: depends on representativeness of observational data and unmeasured confounders.

### Further primary readings
- Antonante, Spivak, Carlone (arXiv 2005.11816v3, early version of IROS 2021) [PRIMARY]: diagnostic graph over perception modules, PMC model: "Fault-free processors are assumed to provide correct test results, whereas no assumption is made about tests executed by faulty processors". Pairwise "consistency functions": input/output admissibility ("consistency checks between any module and its predecessor"), input consistency, output consistency, input/output consistency. Diagnosability (t-diagnosable) bounded by redundancy/test in-degree; temporal diagnostic graphs. Needs: tests per edge. No ground truth, no clean reference, no re-execution, no fault labels (deterministic version). Output: set of faulty modules when diagnosable. The journal version (arXiv 2205.10906, AI 325:103998, adds probabilistic + learning-based variants, Apollo/LGSVL) was read at ABSTRACT level only (PDF over the 10 MB fetch limit).
- Orf et al. 2024, "Modular Fault Diagnosis Framework for Complex Autonomous Driving Systems" (ICCP 2024, arXiv 2411.09643) [PRIMARY, keyword-level read]: per-module diagnosis monitors (threshold/rule/data-driven) + "state- and dependency-aware" aggregation; "we can diagnose the root cause by traversing the graph upon the faulty component"; sensor failure and localization failure injected on AD shuttles; without dependency analysis the fault shows in all parent groups. No GT, no reference run, no re-execution. This IS the "most-upstream deviating node" rule in a robotics stack.
- Rotondi et al., "3D Scene Graphs: Open Challenges and Future Directions" (arXiv 2606.19383, Annual Review CRAS 2026; Hughes and Carlone are co-authors) [PRIMARY]: "Evaluation is the most systemic issue. Most work measures graph quality and downstream task performance independently ... As a result, the effect of perception errors on downstream behavior is rarely quantified directly." Supports the gap statement; it does not claim a diagnosis method exists.

## 4. REVIEWER OBJECTIONS (sharpest first)
1. "Feature engineering plus a textbook rule." Per-layer feature batteries, thresholds, upstream-first blame = PMC/Antonante/Orf on a new graph; your own data say naive max rule is as good; nothing learned, nothing new algorithmically. Defence needs: a setting where the dependency rule or lineage scoping beats the naive rule with a margin outside noise (local, multi-fault, or no-reference), else the contribution is the testbed plus analysis.
2. "Consistency cannot see consistent errors, and the attribution ground truth is circular." Class-consistent label errors and frame drop are invisible by construction (your C7 concedes this), the injected layer is the label so a fault that shows up in its own layer is rewarded, geometric faults count as correct for "mesh or places" (set-valued truth inflates accuracy), masked faults (2 to 6 % query failure) are excluded, thresholds are calibrated on near-harmless perturbations of the same scene, and one scene + one deterministic pipeline + seeds-as-held-out is not generalization. Attribution is of the injected fault, not of an individual failed query.
3. "Why not just intervene?" Hydra is deterministic and the simulator gives GT: IRCA-style oracle substitution (replace a layer's input with GT, re-run, see if the query is fixed) is cheap and is the gold standard for attribution; without it (and without Antonante-style PMC diagnosis and a supervised classifier as baselines) the comparison set is a straw man (max-deviation, majority guess). The no-reference/no-re-execution motivation must be argued for deployment, and C6 must beat a competently built classifier.
(minor) 4. Single-fault only (Han also assumes it; IRCA handles multiple OR faults), so claims about "multiple simultaneous faults" are future work. 5. Room layer fragility (3 % perturbation changes room count) means room-level attribution may measure Hydra's instability, not the injected fault.

## 5. WHAT SURVIVES (positioning for the proposal)
- Defensible gap: nothing found diagnoses hierarchical 3DSG construction; the 2026 survey itself says the effect of perception errors on downstream behaviour is rarely quantified. Existing diagnosis methods split into intervention-based (IRCA: GT oracle + re-execution; CaRE: ~400 runs), hypothesis-library-based (Han: per-fault offline distributions, single fault), and consistency/redundancy-based (Antonante, Orf: no DSG contracts). Unoccupied cell: one finished run, no GT, no re-execution, no fault library, on a derived hierarchy where upper layers are functions of lower ones.
- Position as: layer-labelled fault-injection testbed for hierarchical 3DSG + DSG-specific cross-layer contracts + propagation/masking analysis; NOT "our algorithm is more accurate".
